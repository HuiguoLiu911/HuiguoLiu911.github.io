The question

The second MSBA 6155 assignment moved from one model to several. The task: build a multi-agent team in AutoGen Studio that behaves like a breaking newsroom, give it a crisis prompt, and show that the agents hand off to each other in the right order, pause for a human editor, and stop when the piece is approved. The scenario was fictional: thousands of users of an “OmniBank” mobile app report that a morning patch wiped their visible balances to $0.00, support lines show a four-hour wait, and no automated channel is giving updates.

Data

No dataset. The only inputs are the crisis prompt and the editorial direction typed at the human pause. The Reporter agent browses the live web through a headless Playwright Chromium. The Studio run database and an unredacted team export are excluded from the repo; the published team JSON has the API key replaced with a placeholder.

Method

I built the team as a SelectorGroupChat in AutoGen Studio 0.4.2.2 with a single Azure OpenAI gpt-4o-mini client and five roles:

  • Topic_Generator (AssistantAgent): speaks once, turns raw complaints into a story angle with what to verify and suggested queries.
  • Reporter (MultimodalWebSurfer): verifies the angle on the web and produces a brief.
  • User (UserProxyAgent): the human Editor-in-Chief; the run pauses here for direction.
  • Writer (AssistantAgent): drafts an AP-style article from the brief and the human direction, separating confirmed facts from unresolved claims, and is forbidden from using the word APPROVED.
  • Editor (AssistantAgent): reviews against the brief, the direction and AP objectivity, and either returns targeted feedback (routing back to Writer) or outputs exactly APPROVED.

The key design rule was to put routing logic in each agent’s description, which the selector prompt reads, and behavior rules in the system message. Termination is TextMentionTermination("APPROVED") OR MaxMessageTermination(20). I iterated the team definition through four Python setup scripts before locking the final version in Studio, because the assignment required evidence from the Studio Playground and Team Builder, not from code alone.

Results

  • The run followed the intended order: Topic_Generator, Reporter, User, Writer, Editor, with all five agents speaking and the session ending on APPROVED.
  • At the human pause I steered the story toward the communication failure rather than the app bug itself, and the Writer incorporated that direction without the session losing history.
  • The Editor’s revision loop worked as designed: it asked for revision twice, each time the selector routed the turn back to the Writer, and the run stopped on APPROVED through TextMentionTermination.

What it changed

Delivered the four required artifacts: workflow screenshots of the Playground session, the full session transcript as a Word document, the redacted team JSON export, and a two-paragraph analytical reflection. The reflection’s main point was that the UserProxyAgent is what makes the workflow realistic: a human can review evidence and inject judgment mid-run without cancelling and restarting, which is the pattern production multi-agent systems need.

Limitations and next steps

This is a single scripted scenario, not a benchmark; routing quality depends heavily on how precisely the descriptions are written, and a Reporter that does not clearly finish can confuse the selector. The web-browsing agent is slow and sometimes rate-limited. Next steps would be adding a fact-check agent with explicit source citations and running the same team on several prompts to measure how often routing deviates.
