Scan TikTok for creators without an API

yes& (yesand.ai) · Chrome MV3 extension for multi-keyword creator discovery

Chrome extension (v0.4.9) that searches up to 60 TikTok keywords, dedupes videos and creators, measures median views in KOL mode and exports review-ready CSVs.

The question

Paid scraping actors are the right tool for pulling thousands of profiles, but for the yes& UGC program the team needed something cheaper and more interactive: type a list of keywords, let the browser search TikTok the way a person would, and come back to a shortlist of small creators in a follower band, with a page where a reviewer can watch their videos and rate them. The constraint was no API and no server, just a Chrome extension running in the marketer’s own browser.

Data

The extension works on what TikTok renders: search results, video captions, play, like and share counts, publish dates, and creator profile pages with follower counts and recent-video thumbnails. Each run writes CSVs to a dated folder plus a cumulative creator library. A typical late-August run collected 1,500 videos and shortlisted 180 creators, with 1,057 more recorded as out of range. Exports contain public profile data only and are kept out of the repository.

Method

The extension is plain JavaScript on Chrome’s Manifest V3 APIs: a background service worker orchestrates worker windows, a content script scrolls search pages and reads the DOM, and a popup collects settings. I shipped it in small versions from 0.2.0 to 0.4.9, each fixing something the previous run exposed:

  • Multi-keyword search in four worker windows with global video deduplication across keywords, then creator deduplication with the keywords that found them merged.
  • Wave batching: up to 60 keywords per batch, collected in waves of 12 with a pause between waves so TikTok’s lazy-loading limit refills, and automatic retries for keywords that stop early.
  • KOL mode (from 0.4.0): opens each in-band creator’s profile, reads the real view counts on recent thumbnails and computes a median of the last 15 videos, because pinned and viral videos inflate a mean. Profiling runs three windows in parallel with per-window timeouts.
  • From 0.4.2 the follower band is the only hard filter; median views sort rather than gate, so a blank measurement never empties the shortlist.
  • A generated HTML review panel with lazy-loaded embeds, A/B/C/do-not-send ratings and notes that survive regeneration, and a one-click export in the team’s outreach-sheet format.
  • From 0.4.9, one folder per run with a run_info.txt explaining settings and per-keyword outcomes, plus a _library/creators_master.csv that updates a creator in place when seen again and can exclude already-reviewed creators from the next run.

Two unit test files cover the export paths and an end-to-end export.

Results

  • Keyword-to-shortlist runs that previously needed a paid actor and a spreadsheet now run unattended in the browser and end in a rateable panel.
  • Creator deduplication and the cumulative library stopped the team from re-reviewing the same people across batches.
  • KOL mode gave the team a per-creator median view count that the follower number alone could not, in line with the view-floor metrics used in the Apify pipeline.

What it changed

The extension became the front door of the UGC program: it fed the review panel used to rate creators, and its exports fed the Python funnel and outreach sheet downstream. The changelog itself records a sequence of real operational fixes (stale results skipping a creator, background windows not rendering thumbnails, popups losing typed input) that came from running it daily.

Limitations and next steps

It depends on TikTok’s page structure and rate limits, so selectors and wait times need maintenance. KOL profiling is slower than the fetch-based scan and is meant for the small population above 10,000 followers. Results are what a logged-in browser can see, not a complete index. The natural next step is a direct hand-off into the Python pipeline instead of CSVs.
