An AI copilot for my own job search

A Claude Code workflow that screens postings, tailors a résumé, logs the result

The question

Searching for an analytics role means doing the same three things over and over: reading a posting to see whether I am even eligible, deciding whether it is worth applying, and adjusting my résumé without overstating anything. A general chatbot forgets my rules between conversations and will happily add a skill or a number.

I wanted to know whether I could turn those steps into a repeatable workflow, with fixed rules, that runs entirely inside Claude Code: no model API calls of my own and no website.

Data

Everything is local. Postings come in two ways: pasted by me, or pulled from public applicant-tracking endpoints (Workday, Greenhouse, Lever, Ashby, and Amazon’s job search), never from LinkedIn. A SQLite database holds jobs, fit analyses, tailored drafts and applications, and mirrors a CSV tracker that stays the single source of truth. Résumé content lives as structured JSON: a locked base version and a pool of approved bullets.

Method

The interface is four slash commands, and a SessionStart hook loads the written scoring rules into every session.

  1. /jd: extract the posting’s basics, store it, then run a red-flag scan that quotes any sentence about sponsorship, citizenship or security clearance at the top of the output. An explicit blocker means Skip.
  2. Fit score: six weighted dimensions (skills 25, responsibilities 25, evidence 20, seniority 15, domain 10, education 5), rounded to the nearest 5 so it never looks falsely precise. Evidence is weighted by type, and caps apply when a core skill is missing. A separate priority (High / Medium / Low / Skip) captures eligibility and practical risk.
  3. /tailor: assemble a one-page résumé from the bullet pool, run a wording audit, render the PDF, and self-review before delivery.
  4. /jobs and /discover: a daily dashboard, status updates that write back to the tracker, and a discovery run that deduplicates postings with one shared key definition and writes a markdown digest.

The guardrails are in code, not in prompts. The renderer lets the AI change only the text field of a bullet; layout, section order, company names, titles, dates and education are fixed. Rewording may not add numbers or tools, may not use words on a not-allowed list, and must stay within ±15% of the original length. The automatic screening score is labelled a mechanical approximation and always shows its reasons so I can overrule it.

Results

  • One conversation now covers the path from pasted posting to a reviewed PDF and an updated tracker row.
  • A résumé is delivered only after three checks pass: an automated review checklist, a visual check of the rendered preview, and a re-read from the hiring manager’s point of view.
  • Red-flag sentences appear verbatim at the top, so eligibility problems surface before any tailoring effort.

What it changed

I stopped rewriting résumés from scratch and re-explaining my criteria. The bigger change was where trust sits: the model proposes wording, while facts, structure and scoring rules are fixed in files and code that I can read and edit. When I skip a role I record the reason, which feeds back into the screening criteria.

Next steps

  • Read the tracker’s comparison of résumé versions by outcome once it has 30 or more outcomes.
  • Use the recorded skip reasons to refine the written screening criteria.
